# 1. เอาตัวรอดใน terminal

ทุกอย่างใน ROS 2 ทำผ่าน terminal ถ้าไม่เคยใช้มาก่อน
ครึ่งชั่วโมงนี้แหละที่จะทำให้ทั้งสัปดาห์ที่เหลือไปต่อได้

เปิด terminal ด้วย **Ctrl+Alt+T** ส่วนใน VS Code ใช้ **Ctrl+`** (ปุ่มที่อยู่เหนือ Tab)

## หกคำสั่งพื้นฐาน

| | |
|---|---|
| `pwd` | ตอนนี้อยู่ที่ไหน? |
| `ls` | ในนี้มีอะไรบ้าง? |
| `cd folder` | เข้าไปในโฟลเดอร์ |
| `cd ..` | ถอยกลับขึ้นไปหนึ่งชั้น |
| `cat file` | ดูว่าในไฟล์นี้มีอะไร |
| `clear` | ล้างหน้าจอให้โล่ง |

ลองดู:

```bash
cd ~/AI-Camp
pwd
ls
cd docs
ls
cat 01-terminal.md
cd ..
```

## สองปุ่มช่วยชีวิต

**Tab** ช่วยพิมพ์ต่อให้จนจบ ลองพิมพ์ `cd doc` แล้วกด Tab --
มันจะเติมที่เหลือให้เอง ใช้บ่อย ๆ เลย แถมยังช่วยให้ไม่พิมพ์ชื่อโฟลเดอร์ผิดอีกด้วย

**ลูกศรขึ้น** เรียกคำสั่งล่าสุดกลับมา สัปดาห์นี้จะต้องรันคำสั่งเดิมซ้ำ
ไปซ้ำมาอีกเยอะ ไม่ต้องพิมพ์ใหม่ทุกรอบ

## Ctrl+C

ใช้หยุดโปรแกรมที่กำลังรันอยู่ โปรแกรม ROS 2 จะรันไปเรื่อย ๆ จนกว่าเราจะสั่งหยุด
เพราะฉะนั้นจะได้ใช้ปุ่มนี้บ่อยมาก

ถ้ากด Ctrl+C แล้วไม่หยุด แปลว่าโปรแกรมค้าง -- ปิดแท็บ terminal นั้น
แล้วเปิดอันใหม่

## ต้องเปิดหลาย terminal พร้อมกัน

เรื่องนี้ปกติมากใน ROS 2 หนึ่งโปรแกรมต่อหนึ่ง terminal และรันพร้อมกันทั้งหมด
ใน VS Code ให้คลิก **+** ที่แผง terminal เพื่อเปิดอันใหม่ แล้วคลิกสลับไปมาระหว่างกัน

พอถึงบทที่ 5 จะมีเปิดอยู่สามสี่อัน ไม่ได้ทำอะไรผิดนะ

## คำสั่งเดียวที่ห้ามลืมเด็ดขาด

```bash
source /opt/ros/jazzy/setup.bash
```

(ใช้ `jazzy` บน Ubuntu 24.04 ส่วนบน 22.04 จะเป็น `humble` -- ถ้าไม่แน่ใจ
เช็กด้วย `ls /opt/ros`)

คำสั่งนี้บอก terminal ว่า ROS 2 อยู่ที่ไหน **ทุก terminal ที่เปิดใหม่ต้อง
รันคำสั่งนี้** ถ้าไม่รัน คำสั่ง `ros2` ทุกตัวจะขึ้นว่า "command not found"

พอ build workspace แล้ว ต้องมีอีกบรรทัดหนึ่งด้วย:

```bash
source ~/AI-Camp/ros2_ws/install/setup.bash
```

เท่ากับต้องพิมพ์สองบรรทัดในทุก terminal ทุกครั้ง พิมพ์ไปสักพักก็เบื่อ
เพราะฉะนั้นให้ใส่ไว้ในไฟล์ที่ shell อ่านตอนเริ่มทำงาน:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
echo "source ~/AI-Camp/ros2_ws/install/setup.bash" >> ~/.bashrc
```

บน 22.04 ให้ใช้ `humble` แทน `jazzy` โปรเจกต์อยู่ที่
`~/AI-Camp` และทุกบทเรียนใช้ path นี้

ตอนนี้ terminal ที่เปิดใหม่จะทำให้เองอัตโนมัติ (`>>` คือเพิ่มบรรทัดต่อท้าย
ไฟล์ ส่วน `>` จะ *เขียนทับ* ทั้งไฟล์ -- ระวังตัวนี้ให้ดี)

### มีอยู่ที่หนึ่งที่เรื่องนี้จะเป็นตัวปัญหา

การ source ROS 2 ไว้ในทุก terminal นั้นถูกต้องสำหรับทุกอย่างที่ทำบน
คอมพิวเตอร์ แต่ผิดสำหรับงานอยู่งานเดียว: **การ build firmware ของหุ่นยนต์**
ในบทที่ 5

การ build นั้นจะ compile เครื่องมือ build ของ ROS ชุดส่วนตัวของมันเอง และ
workspace ที่ source ไว้จะทำให้มันสับสน ไม่ต้องจำเรื่องนี้ก็ได้ --
`scripts/build_firmware.sh` จะล้างค่า ROS ให้เอง และบทเรียนก็จะบอกให้ใช้
สคริปต์นี้อยู่แล้ว แค่อย่าแปลกใจว่าทำไมถึงมีสคริปต์นี้

## เช็กว่าใช้ได้แล้ว

เปิด terminal **ใหม่** แล้วรัน:

```bash
ros2 --help
```

ถ้าขึ้นหน้า help มา แปลว่าพร้อมแล้ว ถ้าขึ้นว่า "command not found"
แปลว่าบรรทัด `source` ไม่ได้ทำงาน
