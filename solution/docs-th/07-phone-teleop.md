# 7. ขับหุ่นยนต์ด้วยมือถือ

ไม่บังคับ ทำถ้ามีเวลา

ไม่มีอะไรใหม่ต้องสร้าง ในบทที่ 6 เราขับหุ่นยนต์ด้วยการพิมพ์
`mosquitto_pub` แอปบนมือถือก็ทำแบบเดียวกันเป๊ะ — แค่มี
ปุ่มกดแทนคีย์บอร์ด

```
  ┌────────┐        ┌──────────────┐   /cmd_vel   ┌─────────────┐
  │ phone  │ ─MQTT─>│ mqtt_teleop  │ ───────────> │ esp32_robot │
  │  app   │        │  (gateway)   │              │ (unchanged) │
  └────────┘        └──────────────┘              └─────────────┘
       ^
       └── the only new part. Everything else is lesson 6.
```

## ติดตั้งแอป

**IoT MQTT Panel** มีทั้งบน Android และ iOS

เพิ่ม connection:

| | |
|---|---|
| Broker address | IP ของคอมพิวเตอร์เรา (`hostname -I`) |
| Port | 1883 |
| Client ID | อะไรก็ได้ที่ไม่ซ้ำกับคนอื่น เช่น `phone1` |
| Username / password | เว้นว่างไว้ |

มือถือต้องต่อ **WiFi เดียวกัน** กับคอมพิวเตอร์

### เช็กก่อนไปต่อ

บนคอมพิวเตอร์:

```bash
mosquitto_sub -t 'test/#' -v
```

เพิ่ม Button panel ชั่วคราวในแอป ให้ publish `hello` ไปที่
`test/phone` แล้วกดดู ถ้า message โผล่ขึ้นบนคอมพิวเตอร์ แปลว่า
มือถือคุยกับ broker ได้แล้ว ที่เหลือง่ายมาก ถ้า
ไม่ขึ้น ให้แก้ตรงนี้ก่อน — อย่างอื่นจะใช้ไม่ได้เลยจนกว่าจะแก้ตรงนี้ได้

## เพิ่มปุ่มขับ

**Button** panel ห้าอัน ทุกอัน publish ไปที่ topic เดียวกัน:

```
robot/<ROBOT_ID>/cmd     e.g. robot/test/cmd if config.h says "test"
```

| ปุ่ม | Payload ตอนกด | Payload ตอนปล่อย | ส่งซ้ำระหว่างกดค้าง |
|---|---|---|---|
| เดินหน้า | `F` | `S` | เปิด |
| ถอยหลัง | `B` | `S` | เปิด |
| ซ้าย | `L` | `S` | เปิด |
| ขวา | `R` | `S` | เปิด |
| STOP | `S` | | ปิด |

นี่คือตัวอักษรชุดเดียวกับที่เราพิมพ์ในบทที่ 6 gateway แยกไม่ออก
หรอกว่าเป็นนิ้วโป้งเราหรือคีย์บอร์ด

**เปิด "repeat payload until released"** อันนี้สำคัญ: หุ่นยนต์จะ
หยุดถ้าไม่ได้ยินอะไรเลยภายใน 500 ms ดังนั้นถ้าส่ง message แค่ครั้งเดียวตอนกด
หุ่นยนต์จะกระตุกแล้วหยุด การส่งซ้ำช่วยป้อนคำสั่งให้มันตลอดเวลาที่นิ้วเรา
กดอยู่ และ payload ตอนปล่อยจะสั่งหยุดทันทีที่เราปล่อยนิ้ว

เราเจอ timeout ทั้งสองตัวนี้แล้วในบทที่ 6 นี่แหละคือเหตุผลที่มันมีอยู่

### Slider ปรับความเร็ว (ไม่บังคับ)

เพิ่ม **Slider** panel บน topic เดียวกัน ค่าต่ำสุด `-0.3` ค่าสูงสุด `0.3`
ให้ publish เป็น JSON:

```json
{"lin": <value>, "ang": 0}
```

ตั้ง **live = true** เพื่อให้มัน publish ระหว่างที่เราลาก ไม่ใช่แค่ตอน
ปล่อยนิ้ว

> การตั้ง widget ห้าอันด้วยมือทีละเครื่องช้ามากถ้าทำทั้งห้อง ให้สร้าง
> ครั้งเดียวบนมือถือเครื่องหนึ่ง แล้วใช้ฟีเจอร์ **export configuration**
> ของแอป แชร์ไฟล์นั้นให้เพื่อน — คนอื่นแค่ import เข้าไป

## รันเลย

Agent, หุ่นยนต์ และ gateway ต้องรันอยู่ทั้งหมดเหมือนในบทที่ 6 gateway
ไม่ต้องใช้ IP มีแค่แอปบนมือถือที่ต้องใช้ (`hostname -I` เอา address แรก):

```bash
ros2 launch teleop mqtt_gateway.launch.py
```

กดปุ่ม ควรจะเห็นว่ามันมาถึง:

```
[INFO] [mqtt_teleop]: 'F' -> lin=+0.20 ang=+0.00
```

แล้วหุ่นยนต์ก็ขยับ

## ลองทำดู

1. ขับด้วยมือถือและ `key_teleop` พร้อมกัน ใครชนะ?
2. ปิดแอประหว่างกำลังขับ นานแค่ไหนกว่าหุ่นยนต์จะหยุด? timeout
   ตัวไหนที่ทำให้มันหยุด — ของ gateway หรือของ firmware?
3. มือถือสองเครื่อง broker เดียวกัน topic เดียวกัน เกิดอะไรขึ้น? ถ้าจะ
   ให้แต่ละทีมมีหุ่นยนต์ของตัวเองต้องทำยังไง?
4. เดินออกนอกระยะ WiFi ขณะกดปุ่มเดินหน้าค้างไว้ อะไรควรจะเกิดขึ้น
   และจริง ๆ แล้วเกิดอะไรขึ้น?
5. หุ่นยนต์ของเราเป็น ROS 2 node และมือถือพูด ROS 2 ไม่ได้ — แต่
   มือถือก็ขับมันได้ ลองวาดสายตั้งแต่นิ้วโป้งไปจนถึงมอเตอร์ แล้วเขียนกำกับ
   ว่าแต่ละส่วนพูดภาษาอะไร

## ไปต่อที่ไหนดี

หุ่นยนต์เข้าใจ `/cmd_vel` แปลว่าอะไรก็ตามที่ publish
`/cmd_vel` ก็ขับมันได้ รวมถึงโปรแกรมที่เรายังไม่ได้เขียนด้วย:
node ที่วิ่งตามเส้น หลบสิ่งกีดขวาง หรือรับเส้นทางจาก
Nav2 ไม่มีตัวไหนต้องรู้เลยว่าข้างในหุ่นยนต์มี ESP32

นี่คือสิ่งที่เราได้มาจากการทำให้มันเป็น ROS 2 node ในบทที่ 5
