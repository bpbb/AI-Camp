# 5. หุ่นยนต์ในฐานะ ROS 2 node

ในบทที่ 2 talker และ listener ทำงานอยู่บนคอมพิวเตอร์ ในบทนี้
listener คือตัวหุ่นยนต์

```
  ┌────────────┐      /cmd_vel      ┌─────────────┐
  │ key_teleop │ ─────────────────> │ esp32_robot │
  └────────────┘   Twist message    └─────────────┘
   your keyboard                      the ESP32
```

หลักการเดียวกับ `/chatter` โดยต่างกันที่ชื่อ topic และชนิด message
และ node หนึ่งในนั้นคือ microcontroller ที่ติดตั้งล้อ

## เหตุผลที่ต้องใช้ micro-ROS แทน ROS 2

ROS 2 ไม่สามารถรันบน ESP32 ได้ เนื่องจากทรัพยากรไม่เพียงพอ มิใช่เพียงเพราะประสิทธิภาพต่ำ
ROS 2 node ที่มีขนาดเล็กที่สุดยังต้องใช้หน่วยความจำหลายสิบเมกะไบต์และระบบปฏิบัติการ
เต็มรูปแบบ ขณะที่ ESP32 มี **RAM ประมาณ 320 KB**

**micro-ROS** คือ ROS เวอร์ชันขนาดเล็กที่ออกแบบสำหรับ microcontroller โค้ดที่เขียน
มีลักษณะใกล้เคียงกับ ROS 2 แต่จะสื่อสารผ่าน **agent** ที่รันบนคอมพิวเตอร์ และ
agent เป็นตัวกลางที่นำ micro-ROS เข้าสู่ ROS 2 graph

```
   ESP32                    computer
  ┌────────┐   WiFi       ┌────────┐     ┌──────────────────┐
  │ micro- │ ───────────> │ agent  │ ──> │  the ROS 2 graph │
  │  ROS   │              │        │     │  (your other     │
  └────────┘              └────────┘     │   nodes)         │
                                         └──────────────────┘
```

agent ต้องรันอยู่**ก่อน**ที่หุ่นยนต์จะเชื่อมต่อ หาก ESP32
บูตขึ้นก่อน firmware จะรอและพยายามเชื่อมต่อซ้ำอย่างต่อเนื่อง ซึ่งตรงกับ
สถานะ `WAITING_AGENT` ใน firmware

## Message: Twist

การควบคุมการเคลื่อนที่ของหุ่นยนต์ใช้ค่าสองค่า ได้แก่ ความเร็วในการเดินหน้า และ
ความเร็วในการเลี้ยว ROS 2 มี message มาตรฐานสำหรับวัตถุประสงค์นี้
คือ `geometry_msgs/msg/Twist`:

```
linear.x   metres per second forward   (negative = backwards)
angular.z  radians per second turning  (positive = left)
```

Twist ประกอบด้วยค่าทั้งหมดหกค่า สำหรับหุ่นยนต์ที่เคลื่อนที่ได้ในสามมิติ
หุ่นยนต์สองล้อที่เคลื่อนที่บนพื้นราบใช้เพียงสองค่าข้างต้น

ข้อดีของการใช้ ROS 2 คือ **หุ่นยนต์แบบมีล้อโดยทั่วไปรองรับ
Twist บน `/cmd_vel`** และหุ่นยนต์ในบทนี้ใช้มาตรฐานเดียวกัน

## การตั้งค่า domain ของทีม

หมายเลข domain ที่กำหนดในบทที่ 2 ต้องตั้งค่าไว้สองตำแหน่ง

ตำแหน่งที่ 1: `firmware/include/config.h`:

```c
#define ROS_DOMAIN_ID  7
```

ตำแหน่งที่ 2: คอมพิวเตอร์ ซึ่งได้กำหนดไว้ใน `~/.bashrc` แล้วในบทที่ 2
ให้ตรวจสอบด้วยคำสั่ง:

```bash
echo $ROS_DOMAIN_ID      # ต้องแสดงหมายเลขเดียวกับใน config.h
```

**ค่าทั้งสองต้องตรงกัน** และต้องไม่ซ้ำกับทีมอื่น
หากตั้งค่าผิด คำสั่งจะถูกส่งไปยังหุ่นยนต์ของทีมอื่น

## Upload

**ให้ build จาก terminal ด้วย script ดังนี้:**

```bash
./scripts/build_firmware.sh microros upload
```

ไม่ควรใช้ปุ่ม build ของ VS Code อย่างน้อยในการ build ครั้งแรก ด้วยเหตุผลดังต่อไปนี้

build นี้ compile micro-ROS จาก source รวมถึง
ชุดเครื่องมือ build ของ ROS ที่ micro-ROS มีอยู่ภายในตัวเอง ในบทที่ 1 ได้เพิ่ม ROS 2 ไว้ใน
`~/.bashrc` เพื่อให้โหลดในทุก terminal ซึ่งเป็นสาเหตุของความขัดแย้ง:
build จะพบ ROS ที่ติดตั้งในเครื่องแทนชุดเครื่องมือของตัวเอง และล้มเหลว
พร้อม error ของ CMake จำนวนมากเกี่ยวกับ `rosidl_runtime_cpp` ซึ่งอ้างถึง
workspace ที่ไม่เกี่ยวข้องกับโปรเจกต์นี้

`build_firmware.sh` จะล้างค่าดังกล่าวก่อน build จึงทำงานได้ถูกต้อง
(ปุ่มของ VS Code ใช้งานได้เช่นกัน หากเปิด VS Code
จากเมนูแอปพลิเคชัน มิใช่ด้วยคำสั่ง `code .` ใน terminal
ที่โหลด ROS ไว้แล้ว)

การ compile micro-ROS ใช้เวลา **2-3 นาที** หากเป็นการ build
firmware ครั้งแรกบนเครื่อง จะใช้เวลาเพิ่มประมาณ 8 นาทีสำหรับ
ดาวน์โหลด compiler ของ ESP32 หลังจากนั้นทุกส่วนจะถูก cache ไว้ และ
การ build ซ้ำใช้เวลาเพียงไม่กี่วินาที

ก่อน upload ให้ตรวจสอบว่าใน `firmware/include/config.h` มีข้อมูล WiFi,
IP ของคอมพิวเตอร์ (ค่าแรกจากคำสั่ง `hostname -I`) ใน `AGENT_IP` และ
หมายเลข domain ของทีม หาก upload ไม่สำเร็จ ให้ดู
[troubleshooting.md](troubleshooting.md#the-board-wont-upload)

## Terminal ที่ใช้นับจากนี้

บทนี้ใช้ terminal สามหน้าต่าง `~/.bashrc` ได้ตั้งค่าไว้แล้ว (ROS 2,
workspace นี้ และ domain ของทีม) จึงไม่ต้องพิมพ์คำสั่งเตรียมการใด ๆ หาก
คำสั่งใดแสดง "package not found" หรือไม่พบหุ่นยนต์ ให้ทบทวน
บทที่ 1 และ 2 และตรวจสอบด้วยคำสั่ง:

```bash
echo $ROS_DOMAIN_ID      # หมายเลข domain ของทีม
```

## การเริ่ม agent

Terminal 1:

```bash
./scripts/start_agent.sh
```

เปิด terminal นี้ทิ้งไว้ เมื่อ ESP32 เชื่อมต่อสำเร็จ จะปรากฏข้อความ
`session established` หลายบรรทัด หากไม่ปรากฏข้อความใด แสดงว่าหุ่นยนต์ไม่สามารถติดต่อ
คอมพิวเตอร์ได้ ให้ตรวจสอบ [troubleshooting.md](troubleshooting.md)

## การขับหุ่นยนต์

Terminal 2:

```bash
ros2 run teleop key_teleop
```

ใช้ปุ่ม `w` `a` `s` `d` เพื่อขับ, spacebar เพื่อหยุด และ `q` เพื่อออก

## การตรวจสอบว่า ESP32 เป็น node ใน ROS 2

ขณะที่ทุกส่วนทำงานอยู่ ให้รันคำสั่งต่อไปนี้ใน
terminal 3:

```bash
ros2 node list
```
```
/key_teleop
/esp32_robot      <-- that is the microcontroller
```

```bash
ros2 topic echo /heartbeat
```

ค่าตัวนับนี้ ESP32 เป็นผู้ publish และส่งมาถึงคอมพิวเตอร์

```bash
rqt_graph
```

หุ่นยนต์จะแสดงในแผนภาพร่วมกับ node ของคีย์บอร์ด สำหรับ
ส่วนอื่นของ ROS 2 หุ่นยนต์มีสถานะเทียบเท่ากับโปรแกรมที่รันบนคอมพิวเตอร์

## การขับโดยไม่ใช้คีย์บอร์ด

หุ่นยนต์รับ Twist โดยไม่ขึ้นกับแหล่งที่มา:

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.1}, angular: {z: 0.0}}' -r 10
```

`-r 10` หมายถึงส่งซ้ำสิบครั้งต่อวินาที ให้ทดลองรันโดยไม่ใส่ option นี้: หุ่นยนต์จะ
เคลื่อนที่ครั้งเดียวแล้วหยุด เนื่องจาก safety timeout ใน firmware
จะหยุดมอเตอร์เมื่อไม่มีคำสั่งเข้ามาภายใน 500 ms ให้ค้นหาส่วนนี้ใน
[main.cpp](../firmware/src/microros/main.cpp)

## การบันทึกและเล่นซ้ำ

```bash
ros2 bag record /cmd_vel      # ขับหุ่นยนต์ แล้วกด Ctrl+C เพื่อหยุดบันทึก
ros2 bag play <folder>        # หุ่นยนต์จะเคลื่อนที่ซ้ำตามที่บันทึกไว้
```

เครื่องมือนี้ไม่ได้เขียนขึ้นเฉพาะสำหรับหุ่นยนต์ตัวนี้ แต่ใช้งานได้เนื่องจากหุ่นยนต์สื่อสาร
ด้วยรูปแบบเดียวกับส่วนอื่นทั้งหมดใน ROS 2

## แบบฝึกหัด

1. ปิด agent ระหว่างขับหุ่นยนต์ และสังเกตการทำงานของหุ่นยนต์ จากนั้นเปิด agent ใหม่
   และตรวจสอบว่าหุ่นยนต์กลับมาทำงานได้เองโดยไม่ต้องกด reset หรือไม่
2. รัน `key_teleop` **สอง**ตัวพร้อมกัน และสังเกตผลที่เกิดขึ้น จากนั้นตรวจสอบผลลัพธ์ของ
   `ros2 topic hz /cmd_vel`
3. เปลี่ยน `ROS_DOMAIN_ID` บนคอมพิวเตอร์ โดยไม่เปลี่ยนบนหุ่นยนต์ ตรวจสอบผลลัพธ์ของ
   `ros2 node list` และอธิบายประโยชน์ของการทราบพฤติกรรมนี้
4. รัน `ros2 topic hz /heartbeat` และตรวจสอบว่าได้ค่า 1 Hz พอดีหรือไม่ พร้อมอธิบายเหตุผล
