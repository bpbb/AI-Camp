# 2. Node, topic, publisher, subscriber

บทนี้อธิบายคำศัพท์พื้นฐานของ ROS 2 เมื่อเข้าใจแนวคิดเหล่านี้แล้ว
หุ่นยนต์จะถือเป็นเพียง node อีกตัวหนึ่งในระบบ

## ภาพรวมของแนวคิด

```
   ┌────────────┐                        ┌────────────┐
   │   talker   │ ─────/chatter─────────>│  listener  │
   └────────────┘                        └────────────┘
      a NODE            a TOPIC              a NODE
   (one program)    (a named channel)     (one program)
```

- **node** คือโปรแกรมหนึ่งตัวที่ทำหน้าที่หนึ่งอย่าง
- **topic** คือช่องทางที่มีชื่อกำกับ ใช้สำหรับส่ง message
- node ที่ส่งข้อมูลออกไปยัง topic เรียกว่า **publisher**
- node ที่รับข้อมูลจาก topic เรียกว่า **subscriber**

หลักการสำคัญ: **talker และ listener ไม่มีข้อมูลเกี่ยวกับกันและกัน** ทั้งสอง
ใช้ชื่อ `/chatter` ร่วมกันเท่านั้น หาก node หนึ่งถูก restart ถูกแทนที่
หรือถูกเขียนใหม่ด้วยภาษาอื่น node อีกตัวจะไม่ได้รับผลกระทบ

## การรันโปรแกรม

Terminal 1:

```bash
ros2 run workshop listener
```

โปรแกรมจะแสดงข้อความว่ากำลังรอรับข้อมูล และจะไม่แสดงผลเพิ่มเติม
จนกว่าจะมี message เข้ามา

Terminal 2:

```bash
ros2 run workshop talker
```

ตรวจสอบผลลัพธ์ในทั้งสองหน้าต่าง node ทั้งสองค้นหากันได้เองโดยไม่ต้อง
ระบุ address หรือตั้งค่าเพิ่มเติม ข้อมูลที่ต้องกำหนดมีเพียงชื่อ topic

## การตรวจสอบระบบ

ให้ node ทั้งสองทำงานต่อไป แล้วเปิด terminal ที่สาม:

```bash
ros2 node list
```
```
/listener
/talker
```

```bash
ros2 topic list
```
```
/chatter
/parameter_events
/rosout
```

```bash
ros2 topic echo /chatter
```

คำสั่งนี้เป็นคำสั่งที่ใช้งานบ่อยที่สุดใน ROS 2 โดยจะ subscribe topic
ที่ระบุและแสดง message ทุกรายการที่ส่งผ่าน การรันคำสั่งนี้เท่ากับเป็นการ
เพิ่ม subscriber ตัวที่สามเข้าสู่ระบบโดยไม่ต้องแก้ไขโค้ด

```bash
ros2 topic info /chatter
```
```
Type: std_msgs/msg/String
Publisher count: 1
Subscription count: 2      <-- listener, and your echo
```

```bash
ros2 topic hz /chatter      # แสดงจำนวน message ต่อวินาที
rqt_graph                   # แสดงแผนภาพการเชื่อมต่อของ node และ topic
```

## การ publish โดยไม่ต้องเขียนโปรแกรม

หยุด talker (Ctrl+C) โดยให้ listener ทำงานต่อไป จากนั้นรันคำสั่ง:

```bash
ros2 topic pub /chatter std_msgs/msg/String '{data: "hi from the terminal"}'
```

listener จะได้รับข้อความดังกล่าว และไม่สามารถแยกได้ว่าข้อความมาจาก
terminal หรือจาก talker ซึ่งแสดงให้เห็นว่า node ที่ใช้ topic ร่วมกัน
ไม่ขึ้นต่อกัน

## การแก้ไขโค้ด

เปิดไฟล์ [talker.py](../ros2_ws/src/workshop/workshop/talker.py)
ส่วนต้นของไฟล์มีค่าคงที่ดังนี้:

```python
TOPIC = 'chatter'
MESSAGE = 'hello'
RATE_HZ = 1.0
```

ให้ทดลองแก้ไขทีละรายการ และ build ใหม่ทุกครั้งด้วยคำสั่ง:

```bash
cd ~/AI-Camp/ros2_ws && colcon build && source install/setup.bash
```

1. เปลี่ยนค่า `MESSAGE` เป็นชื่อของผู้เรียน
2. เปลี่ยนค่า `RATE_HZ` เป็น `10.0` แล้วตรวจสอบด้วย `ros2 topic hz /chatter`
3. เปลี่ยนค่า `TOPIC` เป็น `'robot'` ใน talker **โดยไม่เปลี่ยน**ใน listener
   node ทั้งสองจะไม่สามารถสื่อสารกันได้ ให้แก้ไขโดยเปลี่ยนค่าใน listener
   ให้ตรงกัน **ข้อผิดพลาดลักษณะนี้เกิดขึ้นบ่อยกับหุ่นยนต์จริง** จึงควร
   ทำความเข้าใจในขั้นตอนนี้ก่อน

## Workshop: การสื่อสารระหว่างคอมพิวเตอร์

เมื่อคอมพิวเตอร์สองเครื่องเชื่อมต่อ WiFi เดียวกัน และเครื่องหนึ่งรัน talker
อีกเครื่องรัน listener node ทั้งสองจะสื่อสารข้ามเครื่องกันได้โดยไม่ต้อง
ตั้งค่าเพิ่มเติม

อย่างไรก็ตาม เมื่อมีผู้ใช้หลายคนทำงานในเครือข่ายเดียวกันพร้อมกัน talker
ทุกตัวจะ publish ไปที่ `/chatter` และ listener ทุกตัวจะได้รับ message
จาก talker ทุกตัว

วิธีแก้ไขคือการกำหนด **domain** ซึ่งเป็นหมายเลขที่ใช้แยกกลุ่มของ node ออกจากกัน:

```bash
export ROS_DOMAIN_ID=7
```

ให้แต่ละทีมเลือกหมายเลขหนึ่งหมายเลขในช่วง 1 ถึง 101 node ที่อยู่ต่าง
domain กันจะไม่สามารถมองเห็นกัน และจะไม่ปรากฏในผลลัพธ์ของ `ros2 node list`

ค่านี้มีผลเฉพาะใน terminal ที่ตั้งค่าเท่านั้น เช่นเดียวกับบรรทัด `source`
ในบทที่ 1 ให้เพิ่มค่านี้ไว้ใน `~/.bashrc` เพื่อให้ทุก terminal ที่เปิดใหม่
ได้รับค่าเดียวกัน (ใช้หมายเลขของทีม):

```bash
grep ROS_DOMAIN_ID ~/.bashrc        # หากมีบรรทัดนี้อยู่แล้ว ให้แก้ไขบรรทัดเดิมแทน
echo "export ROS_DOMAIN_ID=7" >> ~/.bashrc
```

เปิด terminal **ใหม่** แล้วตรวจสอบ:

```bash
echo $ROS_DOMAIN_ID                 # ต้องแสดงหมายเลขของทีม
```

หาก `grep` พบบรรทัดเดิม เช่น จากโปรเจกต์อื่น ให้เปิด `~/.bashrc`
ใน VS Code และแก้ไขหมายเลขในบรรทัดนั้นแทนการเพิ่มบรรทัดใหม่
หากมีสองบรรทัด ระบบจะใช้ค่าจากบรรทัดสุดท้าย ซึ่งอาจทำให้ไม่ทราบ
ว่าค่าใดมีผลอยู่

บันทึกหมายเลขของทีมไว้ **หมายเลขเดียวกันนี้ต้องใช้กับหุ่นยนต์ในบทที่ 5**

## คำถามทบทวน

1. node และ topic แตกต่างกันอย่างไร
2. หาก listener ไม่ได้ทำงานอยู่ talker จะทำงานอย่างไร
3. หาก node สองตัว publish ไปที่ `/chatter` พร้อมกัน node ใดจะได้รับ message ใดบ้าง
4. หากเปลี่ยนค่า `TOPIC` เพียงไฟล์เดียว จะเกิดผลอย่างไร และจะใช้
   `ros2 topic list` ระบุสาเหตุได้อย่างไร
5. เหตุใดแต่ละทีมจึงต้องใช้ `ROS_DOMAIN_ID` ต่างกัน
