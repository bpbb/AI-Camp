# 0. เตรียมเครื่องให้พร้อม

ทำส่วนนี้ให้เสร็จตั้งแต่วันก่อน อย่ารอไปทำเช้าวันเรียนบทแรก การ build
firmware ครั้งแรกต้องดาวน์โหลดของเยอะมาก และใช้เวลาประมาณ 10 นาที

บทเรียนเรียงตามลำดับนี้ และแต่ละบทต้องผ่านบทก่อนหน้ามาแล้ว:

| | | |
|---|---|---|
| 1 | Terminal | ยังไม่มี ROS ยังไม่ใช้หุ่นยนต์ |
| 2 | Node และ topic | ใช้แค่คอมพิวเตอร์ |
| 3 | ประกอบหุ่นยนต์ | ไม่ต้องใช้ซอฟต์แวร์ |
| 4 | ทดสอบมอเตอร์ | ไม่ต้องใช้เครือข่าย |
| 5 | micro-ROS | หุ่นยนต์เข้าร่วม graph |
| 6 | MQTT | อีกวิธีหนึ่งในการส่ง message |
| 7 | ควบคุมด้วยมือถือ (phone teleop) | ไม่บังคับ |

ยังไม่ต้องใช้หุ่นยนต์จนถึงบทที่ 3 เพราะฉะนั้นถ้าฮาร์ดแวร์มาส่งช้า
ก็ยังเริ่มเรียนได้ตามปกติ

## สิ่งที่ต้องมี

- คอมพิวเตอร์ที่ลง **Ubuntu 24.04** (ROS 2 Jazzy) หรือ **22.04** (ROS 2
  Humble) `setup_pc.sh` จะเช็กให้เองว่าเป็นเวอร์ชันไหน และติดตั้ง ROS 2 ให้ถ้า
  ยังไม่มี เช็กเวอร์ชันของเครื่องตัวเองได้ด้วย `lsb_release -ds`
- **VS Code**
- บอร์ด ESP32 dev board และสาย USB (ต้องเป็นสาย *ส่งข้อมูลได้* -- สายที่ชาร์จ
  ได้อย่างเดียวใช้ไม่ได้ และจะไม่มี error อะไรบอกให้รู้เลย)

## 1. ส่วนขยาย (extension) ของ VS Code

เปิดโฟลเดอร์โปรเจกต์ใน VS Code แล้วมันจะถามว่าจะติดตั้ง extension
ที่แนะนำไหม -- ตอบ yes ไปเลย ถ้ามันไม่ถาม ให้ติดตั้งพวกนี้เอง:

| Extension | ใช้ทำอะไร |
|---|---|
| PlatformIO IDE | build และ upload firmware ลง ESP32 |
| ROS | รองรับ ROS 2 |
| Python | สำหรับ teleop node |

## 2. แพ็กเกจบนคอมพิวเตอร์

```bash
./scripts/setup_pc.sh
```

สคริปต์นี้จะติดตั้ง MQTT broker, ไลบรารี MQTT ของ Python และ build
micro-ROS agent จาก source -- เพราะไม่มี package สำเร็จรูปให้ใช้
ขั้นตอนนี้ใช้เวลาไม่กี่นาที และทำแค่ครั้งเดียวต่อเครื่อง

พอเสร็จแล้วมันจะแสดง IP address ของคอมพิวเตอร์ออกมา **จดเลขนี้
ไว้** เพราะต้องใช้ในขั้นต่อไป

ไม่มีการใช้ docker เลย ทุกอย่างรันบนเครื่องโดยตรง

> บน Ubuntu 24.04 คำสั่ง `pip3 install --user` จะถูกปฏิเสธพร้อมข้อความ
> **`error: externally-managed-environment`** เป็นเรื่องปกติ และไม่เกี่ยว
> อะไรกับเวอร์ชัน Python ของเรา -- 24.04 แค่ป้องกัน Python ของระบบไว้
> `setup_pc.sh` ใช้ `pipx` กับ `apt` แทน เพราะฉะนั้นไม่น่าจะเจอปัญหานี้
> แต่ถ้าเจอ ก็อย่าไปติดตั้ง Python ใหม่

จากนั้นให้สิทธิ์ user ของเราในการ upload ลง ESP32 ผ่าน USB:

```bash
sudo usermod -aG dialout $USER
```

**Log out แล้ว log in ใหม่** (หรือ reboot) เพื่อให้มีผล ถ้าไม่ทำ
การ upload จะ fail พร้อมข้อความ `Permission denied /dev/ttyUSB0`

## 3. บอกหุ่นยนต์ว่าคอมพิวเตอร์ของเราอยู่ที่ไหน

เปิด `firmware/include/config.h` แล้วกรอกข้อมูล:

```c
#define WIFI_SSID      "..."      // your network
#define WIFI_PASSWORD  "..."
#define ROBOT_ID       "robot1"   // your robot name
#define AGENT_IP       "..."      // the IP from step 2
#define ROS_DOMAIN_ID  0          // your team's number -- see lesson 2
```

ลืม IP? รัน `hostname -I` แล้วใช้ address **ตัวแรก** ไม่ต้องสนใจ
`172.17.x.x` -- อันนั้นเป็นของ Docker ไม่ใช่ WiFi ของเรา

จากนั้นเปิด `firmware/platformio.ini` แล้วแก้บรรทัดนี้ให้ตรงกับ ROS 2 ของเรา
(`ls /opt/ros` จะบอกว่าเครื่องเรามีเวอร์ชันไหน):

```ini
board_microros_distro = humble   ; jazzy on 24.04, humble on 22.04
```

ถ้าแก้ค่านี้ ให้ลบ `firmware/.pio` ทิ้งด้วย จะได้ไม่เอาของเก่ามาใช้ซ้ำ

ทุกทีมต้องใช้ `ROBOT_ID` ที่ **ไม่ซ้ำกัน** และ `ROS_DOMAIN_ID` ที่ **ไม่ซ้ำกัน**
ไม่อย่างนั้นจะไปขับหุ่นยนต์ของทีมอื่นกันมั่ว

## 4. Build ROS 2 workspace

```bash
cd ros2_ws
colcon build
source install/setup.bash
```

ต้องมีบรรทัด `source` นี้ใน **ทุก terminal ที่เปิดใหม่** บทที่ 1
เลยจะให้ใส่มันไว้ใน `~/.bashrc` พร้อมกับตัว ROS 2 และบทที่ 2 จะเพิ่ม
`ROS_DOMAIN_ID` ของเราลงไปด้วย หลังจากนั้น terminal ที่เปิดใหม่ทุกอันก็พร้อมใช้ทันที

## 5. Build firmware ไว้ล่วงหน้า

```bash
./scripts/build_firmware.sh motortest
./scripts/build_firmware.sh microros    # อันนี้ช้า ประมาณ 10 นาที
```

รันคำสั่งพวกนี้จากโฟลเดอร์โปรเจกต์ ไม่ใช่จากใน `firmware/` สคริปต์จะ
เลือกโปรแกรมที่ถูกต้องให้ และล้างค่า ROS ที่ไม่อย่างนั้นจะทำให้การ build micro-ROS พัง

ทั้งสองคำสั่งควรจบด้วย `SUCCESS`

ทำอันที่เป็น `microros` **ก่อน** เรียน อย่าไปทำตอนเรียน เพราะมัน compile
micro-ROS จาก source และดาวน์โหลดของเยอะมาก ถ้าคอมพิวเตอร์ยี่สิบเครื่องทำพร้อมกัน
บน WiFi เดียวกัน บ่ายนั้นจะแย่มาก พอ build เสร็จครั้งแรกแล้วมันจะถูก cache ไว้
การ build ครั้งต่อ ๆ ไปใช้เวลาแค่ไม่กี่วินาที

## 6. ตรวจสอบ

```bash
./scripts/check_setup.sh
```

ทุกอย่างควรขึ้นเป็นสีเขียว เช้าวันเรียนแต่ละวันก็ให้รันซ้ำด้วย --
มันจะจับสิ่งที่เปลี่ยนไปข้ามคืนได้ เช่น IP address ของคอมพิวเตอร์ที่เปลี่ยน

## เรื่อง WiFi

หุ่นยนต์และคอมพิวเตอร์ต้องอยู่ใน **เครือข่ายเดียวกัน** และเครือข่ายนั้นต้อง
ยอมให้อุปกรณ์คุยกันเองได้ เครือข่ายของโรงเรียนและเครือข่ายสำหรับแขก (guest)
หลายแห่งตั้งใจบล็อกเรื่องนี้ไว้ ("client isolation") ถ้าภายหลังไม่มีอะไรทำงาน
ทั้งที่ทุกอย่างดูถูกต้อง ส่วนใหญ่สาเหตุคือเรื่องนี้แหละ -- ให้ใช้ router แยกต่างหาก
หรือ hotspot จากมือถือ (ตั้งเป็น 2.4 GHz)

เครือข่าย "guest" แบบเปิดคือกรณีที่แย่ที่สุด: ปกติต้อง login ผ่าน
หน้าเว็บ ซึ่ง ESP32 ทำไม่ได้ *และ* ยังบล็อกไม่ให้อุปกรณ์
เชื่อมต่อถึงกันอีก ถ้า WiFi ที่มีอยู่ไม่มีรหัสผ่านและต้อง login ผ่านหน้าเว็บ
ให้เตรียมใช้ hotspot ไว้เลย
