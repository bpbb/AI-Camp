# 0. การเตรียมเครื่องคอมพิวเตอร์

| | | |
|---|---|---|
| 1 | Terminal | ยังไม่ใช้ ROS และยังไม่ใช้หุ่นยนต์ |
| 2 | Node และ topic | ใช้เฉพาะคอมพิวเตอร์ |
| 3 | การประกอบหุ่นยนต์ | ไม่ใช้ซอฟต์แวร์ |
| 4 | การทดสอบมอเตอร์ | ไม่ใช้เครือข่าย |
| 5 | micro-ROS | หุ่นยนต์เข้าร่วม graph |
| 6 | MQTT | วิธีการส่ง message อีกรูปแบบหนึ่ง |
| 7 | การควบคุมด้วยโทรศัพท์มือถือ (phone teleop) | ไม่บังคับ |

## สิ่งที่ต้องเตรียม

- คอมพิวเตอร์ที่ติดตั้ง **Ubuntu 24.04** (ROS 2 Jazzy) หรือ **22.04** (ROS 2
  Humble) `setup_pc.sh` จะตรวจสอบเวอร์ชันโดยอัตโนมัติ และติดตั้ง ROS 2 ให้หาก
  ยังไม่มี สามารถตรวจสอบเวอร์ชันของเครื่องได้ด้วยคำสั่ง `lsb_release -ds`
- **VS Code**
- บอร์ด ESP32 dev board และสาย USB (ต้องเป็นสายที่ *รองรับการส่งข้อมูล* --
  สายสำหรับชาร์จไฟเพียงอย่างเดียวไม่สามารถใช้งานได้ และระบบจะไม่แสดง error ใด ๆ)

## 1. ส่วนขยาย (extension) ของ VS Code

เปิดโฟลเดอร์โปรเจกต์ใน VS Code ระบบจะสอบถามว่าต้องการติดตั้ง extension
ที่แนะนำหรือไม่ ให้ตอบ yes หากระบบไม่สอบถาม ให้ติดตั้ง extension ต่อไปนี้ด้วยตนเอง:

| Extension | หน้าที่ |
|---|---|
| PlatformIO IDE | build และ upload firmware ลง ESP32 |
| ROS | รองรับการใช้งาน ROS 2 |
| Python | ใช้สำหรับ teleop node |

## 2. แพ็กเกจบนคอมพิวเตอร์

ให้รันคำสั่งต่อไปนี้จากโฟลเดอร์โปรเจกต์:

```bash
bash scripts/setup_pc.sh
```

การเรียกผ่าน `bash` ใช้งานได้แม้คัดลอกโปรเจกต์มาด้วย USB drive หรือไฟล์ ZIP
ซึ่งทำให้สิทธิ์การรันหายไป สคริปต์จะกำหนดสิทธิ์ให้ทุกสคริปต์โดยอัตโนมัติ
หลังจากนั้นจึงใช้ `./scripts/...` ได้ตามปกติ

สคริปต์นี้จะติดตั้ง MQTT broker และไลบรารี MQTT ของ Python รวมทั้ง build
micro-ROS agent จาก source เนื่องจากไม่มี package สำเร็จรูปให้ใช้งาน
ขั้นตอนนี้ใช้เวลาไม่กี่นาที และดำเนินการเพียงครั้งเดียวต่อเครื่อง

เมื่อดำเนินการเสร็จสิ้น สคริปต์จะแสดง IP address ของคอมพิวเตอร์ **ให้บันทึก
หมายเลขนี้ไว้** เนื่องจากต้องใช้ในขั้นตอนถัดไป

ระบบนี้ไม่ใช้ docker ทุกส่วนทำงานบนเครื่องโดยตรง

> บน Ubuntu 24.04 คำสั่ง `pip3 install --user` จะถูกปฏิเสธพร้อมข้อความ
> **`error: externally-managed-environment`** ซึ่งเป็นพฤติกรรมปกติ และไม่เกี่ยวข้อง
> กับเวอร์ชัน Python ของเครื่อง -- 24.04 ป้องกันการแก้ไข Python ของระบบไว้
> `setup_pc.sh` ใช้ `pipx` และ `apt` แทน จึงไม่ควรพบปัญหานี้
> หากพบปัญหานี้ ห้ามติดตั้ง Python ใหม่

จากนั้นให้กำหนดสิทธิ์แก่ user ในการ upload ลง ESP32 ผ่าน USB:

```bash
sudo usermod -aG dialout $USER
```

**ให้ log out แล้ว log in ใหม่** (หรือ reboot) เพื่อให้การตั้งค่ามีผล หากไม่ดำเนินการ
การ upload จะล้มเหลวพร้อมข้อความ `Permission denied /dev/ttyUSB0`

## 3. การกำหนดตำแหน่งคอมพิวเตอร์ให้หุ่นยนต์

เปิดไฟล์ `firmware/include/config.h` แล้วกรอกข้อมูลดังนี้:

```c
#define WIFI_SSID      "..."      // your network
#define WIFI_PASSWORD  "..."
#define ROBOT_ID       "robot1"   // your robot name
#define AGENT_IP       "..."      // the IP from step 2
#define ROS_DOMAIN_ID  0          // your team's number -- see lesson 2
```

หากไม่ทราบ IP ให้รันคำสั่ง `hostname -I` แล้วใช้ address **ตัวแรก** ไม่ต้องใช้
`172.17.x.x` เนื่องจากเป็น address ของ Docker ไม่ใช่ WiFi

จากนั้นเปิดไฟล์ `firmware/platformio.ini` แล้วแก้ไขบรรทัดต่อไปนี้ให้ตรงกับเวอร์ชัน ROS 2 ของเครื่อง
(ตรวจสอบเวอร์ชันที่ติดตั้งได้ด้วยคำสั่ง `ls /opt/ros`):

```ini
board_microros_distro = jazzy    ; jazzy on 24.04, humble on 22.04
```

หากแก้ไขค่านี้ ให้ลบโฟลเดอร์ `firmware/.pio` ด้วย เพื่อป้องกันการนำผลการ build เดิมมาใช้ซ้ำ

แต่ละทีมต้องใช้ `ROBOT_ID` ที่ **ไม่ซ้ำกัน** และ `ROS_DOMAIN_ID` ที่ **ไม่ซ้ำกัน**
มิฉะนั้นคำสั่งอาจถูกส่งไปยังหุ่นยนต์ของทีมอื่น

## 4. Build ROS 2 workspace

```bash
cd ros2_ws
colcon build
source install/setup.bash
```

ต้องรันบรรทัด `source` นี้ใน **ทุก terminal ที่เปิดใหม่** ในบทที่ 1
จะกำหนดให้เพิ่มบรรทัดนี้ไว้ใน `~/.bashrc` พร้อมกับ ROS 2 และในบทที่ 2 จะเพิ่ม
`ROS_DOMAIN_ID` ลงไปด้วย หลังจากนั้น terminal ที่เปิดใหม่ทุกหน้าต่างจะพร้อมใช้งานทันที

## 5. Build firmware ล่วงหน้า

```bash
./scripts/build_firmware.sh motortest
./scripts/build_firmware.sh microros
```

ให้รันคำสั่งเหล่านี้จากโฟลเดอร์โปรเจกต์ ไม่ใช่จากภายใน `firmware/` สคริปต์จะ
เลือกโปรแกรมที่ถูกต้อง และล้างค่าตัวแปร ROS ซึ่งหากไม่ล้างจะทำให้การ build micro-ROS ล้มเหลว

ทั้งสองคำสั่งต้องสิ้นสุดด้วยข้อความ `SUCCESS`

คำสั่ง `microros` จะ compile micro-ROS จาก source และดาวน์โหลดข้อมูลจำนวนมาก
เมื่อ build สำเร็จครั้งแรกแล้ว ผลลัพธ์จะถูก cache ไว้
และการ build ครั้งถัดไปจะใช้เวลาเพียงไม่กี่วินาที

## 6. การตรวจสอบ

```bash
./scripts/check_setup.sh
```

ทุกรายการต้องแสดงผลเป็นสีเขียว
