# 7. การขับหุ่นยนต์ด้วยมือถือ

บทนี้ไม่มีส่วนประกอบใหม่ที่ต้องสร้าง ในบทที่ 6 หุ่นยนต์ถูกขับด้วยคำสั่ง
`mosquitto_pub` แอปบนมือถือทำงานในลักษณะเดียวกัน โดยใช้
ปุ่มกดแทนคีย์บอร์ด

```
  ┌────────┐        ┌──────────────┐   /cmd_vel   ┌─────────────┐
  │ phone  │ ─MQTT─>│ mqtt_teleop  │ ───────────> │ esp32_robot │
  │  app   │        │  (gateway)   │              │ (unchanged) │
  └────────┘        └──────────────┘              └─────────────┘
       ^
       └── the only new part. Everything else is lesson 6.
```

## การติดตั้งแอป

ติดตั้งแอป **IoT MQTT Panel** ซึ่งมีทั้งบน Android และ iOS

เพิ่ม connection ตามค่าต่อไปนี้:

| | |
|---|---|
| Broker address | IP ของคอมพิวเตอร์ (`hostname -I`) |
| Port | 1883 |
| Client ID | ค่าที่ไม่ซ้ำกับอุปกรณ์อื่น เช่น `phone1` |
| Username / password | เว้นว่างไว้ |

มือถือต้องเชื่อมต่อกับ **WiFi เดียวกัน** กับคอมพิวเตอร์

### การตรวจสอบการเชื่อมต่อ

บนคอมพิวเตอร์:

```bash
mosquitto_sub -t 'test/#' -v
```

เพิ่ม Button panel ชั่วคราวในแอป กำหนดให้ publish `hello` ไปที่
`test/phone` แล้วกดปุ่ม หาก message ปรากฏบนคอมพิวเตอร์ แสดงว่า
มือถือเชื่อมต่อกับ broker ได้แล้ว หาก
ไม่ปรากฏ ให้แก้ไขขั้นตอนนี้ก่อน เนื่องจากขั้นตอนถัดไปทั้งหมดจะไม่สามารถทำงานได้

## การเพิ่มปุ่มขับ

เพิ่ม **Button** panel จำนวนห้าปุ่ม ทุกปุ่ม publish ไปที่ topic เดียวกัน:

```
robot/<ROBOT_ID>/cmd     e.g. robot/test/cmd if config.h says "test"
```

| ปุ่ม | Payload เมื่อกด | Payload เมื่อปล่อย | ส่งซ้ำระหว่างกดค้าง |
|---|---|---|---|
| เดินหน้า | `F` | `S` | เปิด |
| ถอยหลัง | `B` | `S` | เปิด |
| ซ้าย | `L` | `S` | เปิด |
| ขวา | `R` | `S` | เปิด |
| STOP | `S` | | ปิด |

ตัวอักษรเหล่านี้เป็นชุดเดียวกับที่ใช้ในบทที่ 6 gateway ไม่สามารถแยกแยะได้
ว่าคำสั่งมาจากมือถือหรือคีย์บอร์ด

**เปิดตัวเลือก "repeat payload until released"** ตัวเลือกนี้มีความสำคัญ เนื่องจากหุ่นยนต์จะ
หยุดหากไม่ได้รับคำสั่งภายใน 500 ms หากส่ง message เพียงครั้งเดียวเมื่อกด
หุ่นยนต์จะเคลื่อนที่ช่วงสั้น ๆ แล้วหยุด การส่งซ้ำทำให้หุ่นยนต์ได้รับคำสั่งต่อเนื่องตลอดเวลาที่
กดปุ่มค้างไว้ และ payload เมื่อปล่อยจะสั่งให้หุ่นยนต์หยุดทันทีที่ปล่อยปุ่ม

timeout ทั้งสองตัวนี้ได้อธิบายไว้แล้วในบทที่ 6

### Slider ปรับความเร็ว

เพิ่ม **Slider** panel บน topic เดียวกัน กำหนดค่าต่ำสุด `-0.3` ค่าสูงสุด `0.3`
และกำหนดให้ publish เป็น JSON:

```json
{"lin": <value>, "ang": 0}
```

ตั้งค่า **live = true** เพื่อให้ publish ระหว่างการเลื่อน slider ไม่ใช่เฉพาะเมื่อ
ปล่อยนิ้ว

> แอปมีฟีเจอร์ **export configuration** สำหรับส่งออกการตั้งค่า widget ทั้งหมดเป็นไฟล์
> ซึ่งสามารถนำไป import บนมือถือเครื่องอื่นได้

## การเริ่มใช้งาน

Agent, หุ่นยนต์ และ gateway ต้องทำงานอยู่ทั้งหมดตามขั้นตอนในบทที่ 6 gateway
ไม่ต้องใช้ IP มีเพียงแอปบนมือถือที่ต้องระบุ IP (ใช้ address แรกจาก `hostname -I`):

```bash
ros2 launch teleop mqtt_gateway.launch.py
```

กดปุ่ม แล้วตรวจสอบว่า gateway ได้รับคำสั่ง:

```
[INFO] [mqtt_teleop]: 'F' -> lin=+0.20 ang=+0.00
```

จากนั้นหุ่นยนต์จะเคลื่อนที่

## แบบฝึกหัด

1. ขับหุ่นยนต์ด้วยมือถือและ `key_teleop` พร้อมกัน คำสั่งใดมีผล
2. ปิดแอประหว่างขับหุ่นยนต์ หุ่นยนต์ใช้เวลานานเท่าใดจึงหยุด และ timeout
   ตัวใดที่ทำให้หุ่นยนต์หยุด ระหว่างของ gateway หรือของ firmware
3. ใช้มือถือสองเครื่องกับ broker เดียวกันและ topic เดียวกัน ผลเป็นอย่างไร หากต้องการ
   ให้แต่ละทีมควบคุมหุ่นยนต์ของตนเองแยกกัน ต้องดำเนินการอย่างไร
4. ออกนอกระยะสัญญาณ WiFi ขณะกดปุ่มเดินหน้าค้างไว้ ผลที่ควรเกิดขึ้นคืออะไร
   และผลที่เกิดขึ้นจริงคืออะไร
5. หุ่นยนต์เป็น ROS 2 node และมือถือไม่รองรับ ROS 2 แต่
   มือถือสามารถขับหุ่นยนต์ได้ ให้วาดเส้นทางของคำสั่งตั้งแต่การกดปุ่มไปจนถึงมอเตอร์ และระบุ
   ว่าแต่ละส่วนใช้โปรโตคอลใด

## การพัฒนาต่อยอด

หุ่นยนต์รับคำสั่งผ่าน `/cmd_vel` ดังนั้นโปรแกรมใดก็ตามที่ publish
`/cmd_vel` สามารถขับหุ่นยนต์ได้ รวมถึงโปรแกรมที่ยังไม่ได้พัฒนา เช่น
node สำหรับวิ่งตามเส้น หลบสิ่งกีดขวาง หรือรับเส้นทางจาก
Nav2 โดยไม่มีโปรแกรมใดจำเป็นต้องทราบว่าภายในหุ่นยนต์ใช้ ESP32

คุณสมบัตินี้เป็นผลจากการทำให้หุ่นยนต์เป็น ROS 2 node ในบทที่ 5
