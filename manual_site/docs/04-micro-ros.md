# 4. หุ่นยนต์เป็น ROS 2 node

ในบทที่ 2 ทั้ง talker และ listener รันอยู่บนคอมพิวเตอร์
บทนี้ "listener" คือ **ตัวหุ่นยนต์** และ "talker" คือ **คีย์บอร์ดของเรา**

```text
  ┌────────────┐      /cmd_vel      ┌─────────────┐
  │ key_teleop │ ─────────────────> │ esp32_robot │
  └────────────┘   Twist message    └─────────────┘
   your keyboard                      the ESP32
```

หลักการเหมือน `/chatter` ทุกอย่าง ต่างกันแค่:

- ชื่อ topic คือ `/cmd_vel`
- message เป็นคำสั่งความเร็ว (Twist) ไม่ใช่ข้อความ
- node ฝั่งรับอยู่บนบอร์ด ESP32 ที่ต่อกับล้อ

## micro-ROS และ agent

ESP32 เป็นบอร์ดเล็กมาก (RAM ประมาณ **320 KB**) รัน ROS 2 เต็มรูปแบบไม่ไหว
จึงใช้ **micro-ROS** ซึ่งเป็น ROS ฉบับย่อสำหรับบอร์ดเล็ก

micro-ROS คุยกับระบบ ROS 2 ผ่านโปรแกรมตัวกลางชื่อ **agent** ที่รันบนคอมพิวเตอร์

```text
   ESP32                    computer
  ┌────────┐   WiFi       ┌────────┐     ┌──────────────────┐
  │ micro- │ ───────────> │ agent  │ ──> │  the ROS 2 graph │
  │  ROS   │              │        │     │  (your other     │
  └────────┘              └────────┘     │   nodes)         │
                                         └──────────────────┘
```

ควรเปิด agent **ก่อน** เปิดหุ่น
ถ้าเปิดหุ่นก่อน หุ่นจะรอและพยายามเชื่อมต่อซ้ำไปเรื่อย ๆ จนกว่า agent จะพร้อม

## Message ที่ใช้สั่งหุ่น: Twist

การสั่งให้หุ่นเคลื่อนที่ใช้ 2 ค่า ซึ่งอยู่ใน message ชื่อ `geometry_msgs/msg/Twist`:

```text
linear.x   metres per second forward   (negative = backwards)
angular.z  radians per second turning  (positive = left)
```

| ค่า | ความหมาย |
|---|---|
| `linear.x` | เดินหน้าเร็วแค่ไหน (m/s) ค่าลบ = ถอยหลัง |
| `angular.z` | หมุนตัวเร็วแค่ไหน (rad/s) ค่าบวก = เลี้ยวซ้าย |

Twist มีทั้งหมด 6 ค่า แต่หุ่นสองล้อที่วิ่งบนพื้นใช้แค่ 2 ค่านี้
หุ่นยนต์ส่วนใหญ่รับคำสั่งแบบนี้ผ่าน topic `/cmd_vel` หุ่นของเราก็เช่นกัน

## ตั้งค่าหุ่นของเครื่องเรา (`config.h`)

เปิดไฟล์ [firmware/include/config.h](../firmware/include/config.h) แล้วแก้ 5 ค่านี้:

```c
#define WIFI_SSID      "..."       // ชื่อ WiFi
#define WIFI_PASSWORD  "..."
#define ROBOT_ID       "robot<เลขเครื่อง>"   // เช่น เครื่องที่ 7 ใส่ "robot7"
#define AGENT_IP       "..."       // IP ของคอมพิวเตอร์
#define ROS_DOMAIN_ID  <เลขเครื่อง>        // เช่น 7 ต้องตรงกับ echo $ROS_DOMAIN_ID
```

### หา IP ของคอมพิวเตอร์ (ใส่ใน `AGENT_IP`)

```bash
hostname -I
```

ผลลัพธ์ที่ควรเห็น (ตัวอย่าง IP ของแต่ละเครื่องจะต่างกัน):

```text
192.168.1.55 172.17.0.1
```

ใช้ตัว **แรก** (ในตัวอย่างคือ `192.168.1.55`) อย่าใช้ตัวที่ขึ้นต้นด้วย `172.17`

### เช็กว่าเลขเครื่องตรงกัน

```bash
cd ~/AI-Camp
echo $ROS_DOMAIN_ID
grep "define ROS_DOMAIN_ID" firmware/include/config.h
```

ผลลัพธ์ที่ควรเห็น (ตัวอย่างของเครื่องที่ 7 ตัวเลขจะต่างกันตามเครื่อง) ตัวเลขสองบรรทัดต้องเหมือนกัน:

```text
7
#define ROS_DOMAIN_ID  7
```

ถ้าเลขไม่ตรงกัน คอมพิวเตอร์จะมองไม่เห็นหุ่น
ถ้าใช้เลขซ้ำกับเครื่องอื่น คำสั่งของเราอาจไปถึงหุ่นของเครื่องอื่น

### build ใหม่หลังแก้ `ROBOT_ID`

โปรแกรมในบทที่ 5 อ่านชื่อหุ่นจาก `config.h` ตอน build จึงต้อง build ใหม่ทุกครั้งที่แก้ `ROBOT_ID`:

```bash
cd ~/AI-Camp/ros2_ws && colcon build && source install/setup.bash
```

## ขับหุ่นด้วยคีย์บอร์ด

**Terminal 2:**

```bash
ros2 run teleop key_teleop
```

**เปลี่ยนแป้นพิมพ์เป็นภาษาอังกฤษ (EN) ก่อนกดปุ่ม**

| ปุ่ม | ทำอะไร |
|---|---|
| `w` / `s` | เดินหน้าเร็วขึ้น / ช้าลง (กดต่อจะถอยหลัง) |
| `a` / `d` | เลี้ยวซ้าย / ขวา มากขึ้น |
| `space` | หยุดทั้งหมด |
| `q` | ออกจากโปรแกรม |

ทุกครั้งที่กดปุ่ม จะเห็นความเร็วปัจจุบันขึ้นมา เช่น `lin=+0.15  ang=+0.00`

> **ปล่อยปุ่มแล้วหุ่นไม่หยุดเอง** ความเร็วจะค้างไว้จนกว่าจะกดปุ่มอื่น หรือกด `space` เพื่อหยุด

### กดแต่ละครั้ง ความเร็วเปลี่ยนเท่าไร

| | เดินหน้า/ถอยหลัง (`w`, `s`) | เลี้ยว (`a`, `d`) |
|---|---|---|
| กดครั้งแรกตอนหยุดอยู่ | ไปที่ ±0.15 m/s ทันที | ไปที่ ±2.0 rad/s ทันที |
| กดครั้งต่อไป | เพิ่ม/ลดครั้งละ 0.05 | เพิ่ม/ลดครั้งละ 0.5 |
| สูงสุด | ±0.30 | ±4.0 |

ทำไมเริ่มที่ 0.15? เพราะถ้าความเร็วต่ำกว่านี้ มอเตอร์จะมีแรงไม่พอที่จะหมุน

ตัวอย่าง: กด `w` 3 ครั้ง ได้ 0.15 → 0.20 → 0.25
แล้วกด `s` 3 ครั้ง ได้ 0.20 → 0.15 → **0.00**

## เช็กว่าหุ่นเป็น node ของ ROS 2 จริง

ขณะที่ทุกอย่างรันอยู่ เปิด **Terminal 3**:

```bash
ros2 node list
```

ผลลัพธ์ที่ควรเห็น:

```text
/esp32_robot
/key_teleop
```

`/esp32_robot` คือบอร์ด ESP32 บนหุ่นของเรา

```bash
ros2 topic echo /heartbeat
```

ผลลัพธ์ที่ควรเห็น (หุ่นส่งตัวเลขมาวินาทีละครั้ง โดยตัวเลขจะเพิ่มขึ้นเรื่อย ๆ):

```text
data: 12
---
data: 13
---
```

```bash
rqt_graph
```

จะเห็นหุ่นอยู่ในภาพร่วมกับ node ของคีย์บอร์ด
ในมุมของ ROS 2 หุ่นของเราก็เป็นแค่ node ตัวหนึ่ง ไม่ต่างจากโปรแกรมบนคอมพิวเตอร์

## ขับโดยไม่ใช้คีย์บอร์ด

หุ่นรับ Twist จากที่ไหนก็ได้ ลองส่งเองจาก terminal (ปิด `key_teleop` ก่อน):

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.1}, angular: {z: 0.0}}' -r 10
```

`-r 10` คือส่งซ้ำวินาทีละ 10 ครั้ง หุ่นจึงวิ่งต่อเนื่อง

**ทดลอง:** ลองไม่ใส่ `-r 10`

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.1}, angular: {z: 0.0}}'
```

หุ่นจะ **วิ่งครึ่งวินาที หยุดครึ่งวินาที สลับกันไปเรื่อย ๆ** เพราะ:

- ถ้าไม่ใส่ `-r` คำสั่งจะถูกส่งแค่ **วินาทีละ 1 ครั้ง**
- หุ่นมีระบบความปลอดภัย: ถ้าไม่ได้รับคำสั่งใหม่ภายใน **0.5 วินาที** จะหยุดมอเตอร์เอง

ค่า 0.5 วินาทีนี้อยู่ใน [main.cpp](../firmware/src/microros/main.cpp) (ค้นหาคำว่า `COMMAND_TIMEOUT_MS`)
