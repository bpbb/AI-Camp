# 7. ขับหุ่นยนต์ด้วยมือถือ

บทนี้ไม่มีโปรแกรมใหม่ให้เขียน
ในบทที่ 6 เราส่งคำสั่ง MQTT ด้วย `mosquitto_pub` บทนี้แค่เปลี่ยนมาส่งจาก **ปุ่มในแอปมือถือ**

```text
  ┌────────┐        ┌──────────────┐   /cmd_vel   ┌─────────────┐
  │ phone  │ ─MQTT─>│ mqtt_teleop  │ ───────────> │ esp32_robot │
  │  app   │        │  (gateway)   │              │ (unchanged) │
  └────────┘        └──────────────┘              └─────────────┘
       ^
       └── the only new part. Everything else is lesson 6.
```

## ขั้นที่ 1: ติดตั้งแอป

1. ติดตั้งแอป **IoT MQTT Panel** (มีทั้ง Android และ iOS)
2. ต่อมือถือเข้า **WiFi เดียวกับคอมพิวเตอร์**

## ขั้นที่ 2: เชื่อมแอปกับ broker

ในแอป สร้าง connection ใหม่ (หน้า **Add Connection**)
กรอกเฉพาะช่องในตาราง ช่องอื่นไม่ต้องแก้:

| ช่อง | ใส่อะไร |
|---|---|
| Connection name | ชื่ออะไรก็ได้ เช่น `robot` |
| Client ID | ชื่อที่ไม่ซ้ำกับมือถือเครื่องอื่น เช่น `phone1` |
| Broker address | IP ของคอมพิวเตอร์ (ดูด้วย `hostname -I` ใช้ตัวแรก) |
| Port | `1883` |
| Network protocol | `TCP` |
| Username / Password (อยู่ใต้ Additional options) | เว้นว่าง |

กด **CREATE**

> ถ้ามือถือสองเครื่องใช้ Client ID เดียวกัน broker จะเตะเครื่องหนึ่งออก จึงต้องตั้งชื่อไม่ซ้ำกัน

### ทดสอบว่าแอปต่อติดแล้ว

**บนคอมพิวเตอร์** รอรับข้อความ:

```bash
mosquitto_sub -t 'test/#' -v
```

**ในแอป**

1. สร้าง Dashboard
2. เพิ่ม panel ชนิด **Button** (ปุ่มทดสอบชั่วคราว) ตั้งค่า:
    - Panel name: `test`
    - Topic: `test/phone`
    - Payload: `hello`
3. กดปุ่มนั้น

ผลลัพธ์ที่ควรเห็นบนคอมพิวเตอร์:

```text
test/phone hello
```

**ถ้าไม่เห็น อย่าเพิ่งไปต่อ** ให้แก้ตรงนี้ให้ได้ก่อน (เช็ก WiFi และ IP) ขั้นต่อไปต้องใช้การเชื่อมต่อนี้

## ขั้นที่ 3: สร้างปุ่มขับหุ่น

### ปุ่มแรก: เดินหน้า

เพิ่ม panel ชนิด **Button** (หน้า **Edit Panel**) กรอกตามนี้ ช่องอื่นไม่ต้องแก้:

| ช่อง | ใส่อะไร |
|---|---|
| Panel name | `Forward` |
| Disable dashboard prefix topic | ไม่ติ๊ก |
| Topic | `robot/<ROBOT_ID>/cmd` เช่น `robot/robot7/cmd` (ดูชื่อหุ่นด้วย `echo $ROBOT_ID`) |
| No payload | ไม่ติ๊ก |
| Payload | `F` |
| Separate payload on release | `S` |
| Repeat publish until released | **ติ๊ก** |
| Repeat interval in milliseconds | `200` |

เปิด agent, หุ่น และ gateway ให้ครบ (ดูหัวข้อ "เริ่มใช้งาน" ด้านล่าง)
แล้วลองกดปุ่ม Forward ค้างไว้ หุ่นต้องเดินหน้า และหยุดเมื่อปล่อยปุ่ม

### ปุ่มที่เหลือ: ใช้ clone

พอปุ่ม Forward ใช้ได้แล้ว ให้ **clone panel** (ทำสำเนาปุ่ม) แล้วแก้แค่ **Panel name** กับ **Payload**:

| ปุ่ม | Panel name | Payload | Separate payload on release | Repeat publish until released |
|---|---|---|---|---|
| เดินหน้า | Forward | `F` | `S` | ติ๊ก, 200 |
| ถอยหลัง | Backward | `B` | `S` | ติ๊ก, 200 |
| ซ้าย | Left | `L` | `S` | ติ๊ก, 200 |
| ขวา | Right | `R` | `S` | ติ๊ก, 200 |
| หยุด | Stop | `S` | **ลบให้ว่าง** | **เอาติ๊กออก** |

ปุ่ม **Stop** ต่างจากปุ่มอื่น 2 ช่อง: ไม่ต้องส่งซ้ำ และไม่ต้องส่งอะไรตอนปล่อยปุ่ม

ปุ่มเหล่านี้ส่งตัวอักษรชุดเดียวกับที่เราพิมพ์ใน `mosquitto_pub` บทที่ 6
gateway จึงทำงานได้เลย มันไม่รู้ด้วยซ้ำว่าคำสั่งมาจากมือถือหรือจาก terminal

### ทำไมต้องติ๊ก Repeat และใช้ 200

- gateway จำคำสั่งล่าสุดไว้แค่ **1 วินาที** ถ้าไม่มีคำสั่งใหม่ จะสั่งหุ่นหยุด
- ถ้าแอปส่งครั้งเดียวตอนกด หุ่นจะขยับแป๊บเดียวแล้วหยุด
- พอติ๊ก Repeat แอปจะส่งซ้ำทุก 200 มิลลิวินาทีตลอดที่กดค้าง หุ่นจึงวิ่งต่อเนื่อง
- ตอนปล่อยปุ่ม แอปส่ง `S` หุ่นจึงหยุดทันที

> **ห้ามใช้ interval เป็น `1000`** เพราะเท่ากับเวลาที่ gateway รอพอดี หุ่นจะกระตุกเป็นพัก ๆ

### Slider ปรับความเร็ว (ทำเมื่อมีเวลา)

slider ในแอปใส่ค่าติดลบไม่ได้ จึงใช้คุมได้แค่การ **เดินหน้า** (ถอยหลังใช้ปุ่ม Backward)

เพิ่ม panel ชนิด **Slider** (หน้า **Add a Slider panel**) กรอกตามนี้ ช่องอื่นไม่ต้องแก้:

| ช่อง | ใส่อะไร |
|---|---|
| Panel name | `Speed` |
| Disable dashboard prefix topic | ไม่ติ๊ก |
| Topic | `robot/<ROBOT_ID>/cmd` (เหมือนปุ่ม) |
| Subscribe Topic | เว้นว่าง |
| Payload min | `0` |
| Payload max | `0.3` |
| Slider step | `0.05` |
| Decimal precision | `2` |
| Factor | `1` (ค่าเดิม) |
| Payload is JSON Data | **ติ๊ก** (จะมีช่อง JSON pattern for publish โผล่ขึ้นมา) |
| JSON pattern for publish | `{"lin": <value>, "ang": 0}` (ตรง `<value>` ให้ใช้ตัวแทนค่าตามที่ปุ่ม **?** ข้างช่องบอก) |

เช็กว่าแอปส่งอะไรออกไป โดยเลื่อน slider แล้วดูบนคอมพิวเตอร์:

```bash
mosquitto_sub -t 'robot/#' -v
```

ผลลัพธ์ที่ควรเห็น:

```text
robot/robot7/cmd {"lin": 0.15, "ang": 0}
```

> หุ่นจะขยับ **เฉพาะตอนที่กำลังเลื่อน slider** เพราะแอปส่งข้อความเฉพาะตอนค่าเปลี่ยน
> พอหยุดเลื่อน gateway จะสั่งหุ่นหยุดภายใน 1 วินาที

## เริ่มใช้งาน

ต้องเปิด agent, หุ่น และ gateway ครบเหมือนบทที่ 6
(ใส่ IP แค่ในแอปมือถือ gateway ไม่ต้องใส่):

```bash
ros2 launch teleop mqtt_gateway.launch.py
```

กดปุ่มในแอป แล้วดูที่ terminal ของ gateway

ผลลัพธ์ที่ควรเห็น:

```text
[INFO] [...] [mqtt_teleop]: 'F' -> lin=+0.20 ang=+0.00
```

แล้วหุ่นก็จะขยับ

## ลองทำเองภายหลัง

ส่วนนี้ไม่บังคับ สามารถลองทำเองได้ในภายหลัง

1. ขับด้วยมือถือและ `key_teleop` พร้อมกัน คำสั่งไหนมีผล
2. ปิดแอประหว่างขับ หุ่นหยุดภายในกี่วินาที ตัวจับเวลาตัวไหนทำให้หยุด (ของ gateway หรือของ firmware)
3. ใช้มือถือสองเครื่อง ส่งไป broker และ topic เดียวกัน เกิดอะไรขึ้น
   ถ้าอยากให้แต่ละทีมขับหุ่นของตัวเองแยกกัน ต้องทำอย่างไร
4. กดปุ่มเดินหน้าค้างไว้ แล้วเดินออกไปไกลจน WiFi หลุด สิ่งที่ควรเกิดคืออะไร และเกิดอะไรขึ้นจริง
5. มือถือไม่รู้จัก ROS 2 แต่ก็ขับหุ่นได้ ลองวาดเส้นทางของคำสั่งตั้งแต่กดปุ่มจนถึงมอเตอร์
   และบอกว่าแต่ละช่วงใช้วิธีส่งแบบไหน (MQTT, ROS 2 หรือสายไฟ)

## ต่อยอด

หุ่นรับคำสั่งผ่าน `/cmd_vel` ดังนั้น **โปรแกรมไหนก็ได้** ที่ส่ง Twist เข้า `/cmd_vel` ก็ขับหุ่นได้
เช่น โปรแกรมวิ่งตามเส้น หลบสิ่งกีดขวาง หรือวางแผนเส้นทางอัตโนมัติ (Nav2)
โปรแกรมเหล่านั้นไม่ต้องรู้เลยว่าข้างในหุ่นคือ ESP32

ที่ทำแบบนี้ได้ เพราะในบทที่ 5 เราทำให้หุ่นเป็น ROS 2 node
